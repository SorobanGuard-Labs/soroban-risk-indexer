# API Reference

All endpoints return JSON responses. List endpoints return `{ "data": [...] }`.

For machine-readable OpenAPI 3.0 specifications, see [`docs/openapi.yaml`](openapi.yaml). You can render this specification using Swagger Editor, Swagger UI, or Redoc.

---

## Endpoints

### 1. `GET /health`

Returns service availability and health.

**Response `200 OK`**:
```json
{
  "status": "ok",
  "service": "soroban-risk-indexer"
}
```

---

### 2. `GET /projects`

Returns list of indexed Soroban projects with computed audit readiness and risk scores.

**Response `200 OK`**:
```json
{
  "data": [
    {
      "id": "project-phoenix-vault",
      "name": "Phoenix Vault",
      "repositoryUrl": "https://github.com/sorobanguard-labs/phoenix-vault",
      "network": "testnet",
      "readinessScore": 85,
      "riskScore": 25
    }
  ]
}
```

---

### 3. `GET /risks`

Returns indexed contract, architectural, and operational risks.

**Response `200 OK`**:
```json
{
  "data": [
    {
      "id": "risk-001",
      "projectId": "project-phoenix-vault",
      "title": "Missing authorization guard on admin path",
      "severity": "high",
      "category": "access-control",
      "description": "A privileged operation is documented but not represented in the readiness checklist.",
      "recommendation": "Require explicit admin authorization tests before promoting the contract.",
      "status": "open"
    }
  ]
}
```

---

### 4. `GET /findings`

Returns audit findings across indexed projects.

**Response `200 OK`**:
```json
{
  "data": [
    {
      "id": "finding-001",
      "projectId": "project-phoenix-vault",
      "severity": "medium",
      "summary": "Boundary test missing for minimum deposit",
      "affectedArea": "deposit validation",
      "recommendation": "Add minimum and zero-value deposit tests.",
      "status": "triaged"
    }
  ]
}
```

---

### 5. `GET /tasks`

Returns readiness and security contributor tasks generated by Soroban Guard Kit or manual checklists.

**Response `200 OK`**:
```json
{
  "data": [
    {
      "id": "task-001",
      "projectId": "project-phoenix-vault",
      "title": "Add admin authorization regression tests",
      "labels": ["security", "authorization", "guard-kit"],
      "difficulty": "medium",
      "acceptanceCriteria": [
        "Admin-only functions have negative authorization tests",
        "CI runs the new tests on every pull request"
      ],
      "status": "in-progress",
      "source": "guard-kit",
      "category": "authorization"
    }
  ]
}
```

---

### 6. `GET /test-results`

Returns test results and Soroban Testbench simulation evidence.

**Query Parameters**:
- `status` *(optional)*: Filter by execution status (`passed`, `failed`, `skipped`).
- `projectId` *(optional)*: Filter by project identifier.
- `simulationType` *(optional)*: Filter by Testbench simulation type (`transaction_simulation`, `rpc_failure`, `auth_boundary`, `budget_exhaustion`, `storage_footprint`).

**Example Request**:
```bash
curl "http://localhost:4100/test-results?simulationType=rpc_failure&status=failed"
```

**Response `200 OK`**:
```json
{
  "data": [
    {
      "id": "test-result-002",
      "projectId": "project-horizon-escrow",
      "scenario": "submit during RPC timeout",
      "status": "failed",
      "durationMs": 930,
      "failureReason": "Submission retry policy was not configured in mock mode.",
      "simulationType": "rpc_failure",
      "rpcDetails": {
        "endpoint": "https://soroban-testnet.stellar.org",
        "rpcError": "GatewayTimeout (504)",
        "retryAttempts": 3,
        "transient": true
      },
      "timestamp": "2026-11-09T03:00:00.000Z"
    }
  ]
}
```

---

### 7. `POST /index/mock`

Refreshes the in-memory store with deterministic mock data and recomputes readiness scores.

**Response `202 Accepted`**:
```json
{
  "data": {
    "projectCount": 2,
    "riskCount": 3,
    "findingCount": 2,
    "taskCount": 3,
    "testResultCount": 2
  }
}
```
